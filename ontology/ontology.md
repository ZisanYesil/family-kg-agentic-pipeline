# 2Wiki RDF Ontology Decisions

This document records the modeling decisions used for the ground-truth RDF
files generated by `example_extraction.py` and the ontology implemented in
`ontology.ttl` and `SHACL_shapes.ttl`.

## Turtle representation

Predicates are written as Turtle prefixed names:

```turtle
@prefix ex: <http://example.org/2wiki-ontology#> .

<http://www.wikidata.org/entity/Q6926481>
    ex:hasDirector
    <http://www.wikidata.org/entity/Q966078> .
```

`ex:hasDirector` is the compact representation of the following full URI:

```text
http://example.org/2wiki-ontology#hasDirector
```

Therefore, `ex:hasDirector` is not plain text; it is a valid RDF predicate URI.

## Namespace decision

The current temporary namespace is:

```text
http://example.org/2wiki-ontology#
```

`example.org` is a reserved domain intended for examples and documentation.
When the permanent ontology is published, this value must be replaced with a
stable HTTPS URI owned by the project. Predicate local names such as
`hasDirector` should remain unchanged during that migration.

after both `RELATION_MAP` and this document have been updated.

## Entity URIs

- Values consisting of `Q` followed by digits are converted to real Wikidata
  URIs: `Q966078` becomes `http://www.wikidata.org/entity/Q966078`.
- When `evidences_id` is unavailable, the current script uses `evidences` as a
  backward-compatible fallback. Names and dates in that field do not have
  QIDs, so temporary URIs under `http://example.org/entity/` are generated.
- Temporary entity labels are losslessly percent-encoded, preventing labels
  containing `?`, `#`, `%`, quotes, or similar characters from changing IRI or
  Turtle syntax and preventing space/underscore collisions.
- In the permanent knowledge graph, name-based temporary URIs should be
  reconciled with Wikidata QIDs whenever possible.

## Date values

- Full dates are emitted as canonical `xsd:date` literals.
- Year-only values retain their original precision as `xsd:gYear` literals.
- When `evidences_id` contains the `date_information` placeholder, its lexical
  value is recovered from the corresponding relation occurrence in
  `evidences`; this does not assume identical global ordering of the lists.

## Explicit types and validation

Generated files include explicit `rdf:type` statements derived from the
relation contract. This lets `SHACL_shapes.ttl` validate data even when RDFS or
OWL inference is disabled. Agent-valued properties use the shared `ex:Agent`
class because the source does not always distinguish a person from an
organization.

The ontology intentionally does not declare broad top-level classes disjoint
yet. The source contains a small number of identifiers or fallback labels used
in incompatible roles (for example both person and creative-work roles). Those
cases require entity-resolution review before disjointness can be enabled.

## Generation source

- `text_N.txt` contains all context titles and sentences from a record,
  including distractor passages.
- `ground_truth_N.ttl` is generated primarily from `evidences_id`; when that
  field is empty, the script falls back to the `evidences` triples.
- Each example is stored under `dataset/N/originals/`, where `text_N.txt` and
  `ground_truth_N.ttl` stay together.
- Because `LIMIT = 100`, the current `dataset` output contains the first 100
  records from `train.json`.

Ground-truth files must not be edited manually or through bulk text
replacement. A change must first be applied to the generation script and this
document, after which the outputs must be regenerated by running the script.

## Verification

Install the pinned dependency ranges and run the regression suite and SHACL
validation from this directory:

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest -v test_ontology.py test_reasoner.py test_vector_entity_matching.py
python3 validate_ontology.py dataset
python3 validate_ontology.py dataset --pattern 'extracted_*.ttl'
```

`sh:Warning` results report Wikidata single-best-value conflicts but do not
make the command fail. SHACL violations produce a non-zero exit status.

## HermiT reasoning

The reasoner requires Java and Owlready2. It accepts one or more Turtle files
or directories; directories contribute their top-level `.ttl` files.

```bash
java -version
python3 reasoner-inference/reasoner_kg_hermit.py dataset/0/originals/ground_truth_0.ttl
python3 reasoner-inference/reasoner_kg_hermit.py dataset --summary-only
python3 reasoner-inference/reasoner_kg_hermit.py dataset --pattern 'extracted_*.ttl' --summary-only
python3 reasoner-inference/reasoner_kg_hermit.py dataset/0/originals/ground_truth_0.ttl \
  --output-ttl materialized.ttl \
  --inferred-output-ttl inferred.ttl
```

Property closure (`rdfs:subPropertyOf`, `owl:inverseOf`,
`owl:equivalentProperty`, and symmetric properties) is completed by default
because some HermiT/Owlready2 exports omit property assertions. Use
`--no-property-closure` only when the raw HermiT synchronization result is
specifically required. Asserted datatype facts such as dates are preserved in
materialized output. SHACL validation remains a separate step: HermiT performs
OWL entailment and consistency checking, not SHACL constraint validation.

## Vector entity matching

The vector matcher resolves entities from an extracted project graph against a
ground-truth graph. It reads `id_aliases.json` as JSON Lines and combines
ontology class compatibility, URI/label/alias variants, object relations,
datatype literals, sentence embeddings, lexical similarity, and Hungarian
one-to-one assignment.

Direct graph-pair mode:

```bash
python3 vector_entity_matching.py \
  --extracted-graph extracted_0.ttl \
  --ground-truth-graph dataset/0/originals/ground_truth_0.ttl \
  --output match_0.json \
  --same-as-output same_as_0.ttl
```

Indexed batch mode pairs filenames by their trailing integer, such as
`extracted_7.ttl` with `ground_truth_7.ttl`:

```bash
python3 vector_entity_matching.py \
  --extracted-dir extracted \
  --ground-truth-dir dataset \
  --output-dir entity_matching_results \
  --write-canonicalized
```

Model downloads are disabled by default. If the model is not cached, permit
its initial download explicitly with `--allow-model-download`. JSON decisions
and separate `owl:sameAs` files are the safe default; canonicalized Turtle is
opt-in. Scores below the threshold are rejected, while assignments without a
sufficient margin over the best alternative are marked `review` rather than
rewritten.

## Question-focused extraction pipeline

The agent pipeline reads `text_N.txt` plus question `N` from `train.json`; it
never sends `ground_truth_N.ttl` to the model. Generated stage artifacts are
written beside the source text by default and existing complete stages are
reused unless `--overwrite` is explicit.

Run only the first twenty dataset IDs:

```bash
.venv/bin/python run_agent_pipeline.py dataset --ids 0-19 --dry-run
.venv/bin/python run_agent_pipeline.py dataset --ids 0 --stop-on-error --stop-on-review
```

Each `dataset/N/originals/` directory receives `extracted_N.ttl`; stage details
(`extraction_N.json`, `mapping_N.json`, `shacl_N.json`, and `shacl_N.ttl`) are
stored under `dataset/N/originals/artifacts/`. A result is marked
`completed` only when there are no unmapped or dangling relations and SHACL
conforms; otherwise it is marked `review`.
